## What the Android APK can contribute

**The Android `libcdkapp.so` cannot link into an iOS app.** I used the installed Xcode iPhoneOS SDK to build a minimal ARM64 iOS Mach-O executable, then repeated the link with the APK's ARM64 `libcdkapp.so`. Apple's linker returned `ld: unknown file type`. `file` identifies the Android library as ELF, and `xcrun llvm-objdump -p` reports Android dependencies including `libandroid.so`, `libjnigraphics.so`, `libEGL.so`, `libGLESv3.so`, and `libc++_shared.so`. The exported JNI methods connect the library to the Android Java runtime. Shared ARM64 instructions leave the file format, runtime ABI, and system libraries incompatible. [Android NDK ABI documentation](https://developer.android.com/ndk/guides/abis) · [Apple platform-specific binary framework documentation](https://developer.apple.com/documentation/xcode/creating-a-multi-platform-binary-framework-bundle) · [Local native symbol inventory](../decrypts/libcdkapp/symbols.demangled.txt)

**CDK3 contains an iOS platform layer.** The local copy matches the public CDK3 README, which describes CDK3 as a later development of the engine behind Tales Craft and ACIES. The source contains an Objective-C++ app delegate and OpenGL ES view as well as iOS file, sound, and URL bridges. I found a Windows solution and an Android CMake file in the local drop, with no iOS Xcode project. The public engine source does not supply the shipped ACIES gameplay client. The Android binary contains game-specific code such as `UnitData`, `Map`, and `PVPGateway`, and several ACIES XMF schemas differ from the public engine’s readers. Verify the source license with the maintainer before depending on it for a distributed build. [CDK3 README](https://github.com/56-13/CDK3/blob/57cdd85da2f6022c983b327c1fe4348c4809841a/README.md) · [CDK3 iOS sources](https://github.com/56-13/CDK3/tree/57cdd85da2f6022c983b327c1fe4348c4809841a/client/src/CDK/Sources/Platform/ios) · [Local schema research](acies-cdk3-xmf-reverse-engineering.md)

**The usable pieces are the data and the backend work.** The decoded localization, maps, images, meshes, animation and audio give us inputs to compare or load. Android packs include ETC2 textures, and the exact iOS resource layout, asset versions, texture variants, and game-data readers remain unknown. The mock backend can be extended once the original iOS client's admission and guest-login behavior is verified. Its current Android emulator address `10.0.2.2` needs a phone-reachable replacement for a native device test. Development signing and iOS networking requirements depend on the recovered build. [Local image decoder](../tools/decode_cdk_image.py) · [Local schema research](acies-cdk3-xmf-reverse-engineering.md) · [Mock backend](acies-local-mock-backend.md) · [Apple local network guidance](https://developer.apple.com/documentation/technotes/tn3179-understanding-local-network-privacy)

## Recovery order

1. **Ask Saint Joy Korea for 2.5.1, an internal iOS build intended for preservation, or the matching game source and Xcode project.** Include both identifiers and ask for the original resources, third-party dependency versions and a local-backend configuration if available. CreaGames is the next lead for a pre-rename archive, and the CLASSWIRE LIMITED seller name can help identify which account published it. BR Games is the lead for the original engine and Tales Craft. The existing contact notes record historical leads and limits. [Publisher and studio contacts](acies-rights-and-shutdown-research.md#who-to-contact) · [Original Clash App Store capture](https://web.archive.org/web/20210119092520id_/https://apps.apple.com/us/app/clash-of-legions-rise-war/id1515733807)
2. **Check accounts that previously downloaded the game and devices that still have it installed.** Apple says apps removed from sale can remain available in purchase history when the necessary contract is active. A genuine standalone IPA export or cached app-library package is worth looking for because ordinary Finder and iCloud backups exclude App Store content. Preserve an existing installation while checking availability on another device. [Apple redownload instructions](https://support.apple.com/en-us/102417) · [Apple removal and redownload conditions](https://developer.apple.com/help/app-store-connect/manage-your-apps-availability/manage-availability-for-your-app-on-the-app-store/) · [Apple backup contents](https://support.apple.com/en-us/108771)
3. **If any iOS build turns up, preserve and inspect it before attempting changes.** Record provenance and a SHA-256 hash. Read `Info.plist` for `CFBundleIdentifier`, `CFBundleShortVersionString`, `CFBundleVersion`, and the executable name. Inventory the Mach-O platform, architectures and dependencies along with the original asset manifest. An older 1.9.x build should first be tested with its own assets and a version-matched mock. Compare XMF file sets and hashes, resource versions, texture encodings, and protocol expectations before substituting individual files. Battle Runes 2.0.3 added runes and other progression systems, so expecting a 1.9.x executable to read all 2.5.1 assets or reproduce its behavior is unsupported. [Apple bundle keys](https://developer.apple.com/documentation/bundleresources/bundle-configuration) · [Apple version history capture](https://web.archive.org/web/20220626035256/https://apps.apple.com/kr/app/acies-battle-runes/id1515733807)

For the original-client preservation goal, the next proof is a recovered iOS build reaching guest login and the lobby against the local server. A fresh Xcode build from CDK3 could test a narrow asset-loading hypothesis, such as rendering one known map or image. Full client parity would require the matching ACIES game source or substantial new gameplay, UI, and protocol work.
